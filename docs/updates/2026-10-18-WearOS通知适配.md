# 更新说明：Wear OS 媒体通知适配（PlayerNotificationManager）

> 前置文档：[播放通知与媒体控制](2026-10-18-播放通知与媒体控制.md)
>
> 对应改动：Wear OS 分支（本文）。Android 9 非 Wear 手表的 RemoteViews 方案仍以前置文档为准。
>
> 目标读者：需要把 Wear OS 适配合并到新版上游代码的维护者。

---

## 1. 背景

前置版本已经做了两条通知路径：

1. Android 10+：`Notification.MediaStyle`。
2. Android 9 及以下（非 Wear 手表）：自定义 `RemoteViews` 紧凑控制条。

但 **Wear OS 对自定义通知布局有限制**：`RemoteViews` 在 Wear OS 上会被系统降级/折叠，不能可靠地显示自绘按钮；Wear OS 的媒体通知应该交给 `androidx.media3.ui.PlayerNotificationManager`（下称 PNR）。它会用 `NotificationCompat` + `MediaStyle` 构建符合 Wear 媒体模板的通知，并自动监听 `Player` 刷新播放状态、切歌和封面。

因此新增第三条路径：

| 设备 | 通知实现 | 控制键 |
|---|---|---|
| Wear OS（FEATURE_WATCH / uiMode=WATCH） | `PlayerNotificationManager`（media3-ui） | 上一首、播放暂停、下一首（系统媒体模板） |
| Android 9 及以下、非 Wear 手表 | 自定义 `RemoteViews` 紧凑条 | 上一首、播放暂停、下一首、关闭 X |
| Android 10+ 非 Wear 设备 | `Notification.MediaStyle` | 上一首、播放暂停、下一首 |

**关键原则：Wear OS 分支绝不使用 `RemoteViews`。**

---

## 2. 判定逻辑

```kotlin
private val isWearOs: Boolean
    get() = packageManager.hasSystemFeature(PackageManager.FEATURE_WATCH) ||
        (resources.configuration.uiMode and Configuration.UI_MODE_TYPE_MASK) ==
        Configuration.UI_MODE_TYPE_WATCH
```

- 只认 `FEATURE_WATCH` 和 `uiMode`，**不要用屏幕宽度判断 Wear OS**。
- 部分国产 Android 9 手表是小屏、但不是 Wear OS（实测 `FEATURE_WATCH=0`、`uiMode` 也不是 WATCH），它们必须继续走 `RemoteViews`。
- `legacyCompact`（`SDK_INT <= 28`）只用于「非 Wear」的 RemoteViews 路径；Wear OS 2（API 28）也会优先命中 PNR 分支。

通知渠道：

| 渠道 ID | 分支 | 重要性 |
|---|---|---|
| `playback_wear` | Wear OS / PNR | `IMPORTANCE_DEFAULT` |
| `playback_watch` | Android 9 非 Wear / RemoteViews | `IMPORTANCE_DEFAULT` |
| `playback` | 其他设备 / MediaStyle | `IMPORTANCE_LOW` |

## 3. 实现原理

### 3.1 PNR 的创建

```kotlin
val manager = PlayerNotificationManager.Builder(this, NOTIF_ID, CHANNEL_ID_WEAR)
    .setMediaDescriptionAdapter(WearDescriptionAdapter())
    .setChannelNameResourceId(R.string.notif_channel_playing)
    .setChannelDescriptionResourceId(R.string.notif_channel_playing_desc)
    .setChannelImportance(NotificationManager.IMPORTANCE_DEFAULT)
    .setSmallIconResourceId(R.drawable.ic_notif_w)
    .setPlayActionIconResourceId(R.drawable.ic_notif_play)
    .setPauseActionIconResourceId(R.drawable.ic_notif_pause)
    .setPreviousActionIconResourceId(R.drawable.ic_notif_prev)
    .setNextActionIconResourceId(R.drawable.ic_notif_next)
    .setNotificationListener(...)
    .build()
```

- `NOTIF_ID` 与前置版本的前台通知 ID 相同（42），保证 PNR 的通知可以接管为前台通知，不会出现两条。
- `setChannelImportance(DEFAULT)`：Wear 上 LOW 渠道可能被折叠。
- `setMediaSessionToken(PlayerEngine.mediaSessionToken)`：平台 `android.media.session.MediaSession.Token` 重载，让 PNR 生成的 MediaStyle 与系统媒体面板/蓝牙共用同一会话。
- `setUsePreviousAction / setUseNextAction / setUsePlayPauseActions(true)`；关闭 stop / rewind / fast-forward。
- `setUsePreviousActionInCompactView / setUseNextActionInCompactView(true)`：Wear 紧凑视图也能看到切歌键。

### 3.2 前台服务契约：占位通知 + 同 ID 接管

PNR 构建/更新通知是异步的，但 `startForegroundService()` 要求 5 秒内必须 `startForeground()`。做法：

1. `onStartCommand` 先 `startForeground(NOTIF_ID, buildWearPlaceholder())`，用同一 ID/渠道发一个最小通知，满足系统契约。
2. 创建 PNR 并 `setPlayer(wrapped)`。
3. PNR 的 `NotificationListener.onNotificationPosted` 回调里执行 `startForeground(notificationId, notification)`，用同一 ID 把占位通知替换成完整的媒体通知。
4. 后续 PNR 更新通知时也会走这个回调，重复 `startForeground` 是同 ID 更新，不会产生第二条通知。

占位通知只包含小图标、歌名、歌手、点击回 App，不包含控制键；PNR 通常会在几十毫秒内覆盖它。

### 3.3 共享 `EnginePlayer`：PNR 不能直接操作 ExoPlayer

PNR 的上一首/下一首会调用 `player.seekToNext()` / `seekToPrevious()`；播放暂停会调用 `player.play()` / `pause()`。但本项目的队列、播放模式、一起听协调都在 `PlayerEngine`，而 ExoPlayer 每次只 `setMediaItem` 载入**一首**：

- 直接 `seekToNextMediaItem()` 只会原地不动；
- 直接 `pause()` 不会同步 `fgWanted`、收听时长、一起听状态。

因此把原 `MusicSessionService` 里的私有 `EnginePlayer` 抽成共享类 `EnginePlayer.kt`，PNR 和 Media3 会话都使用它：

```kotlin
internal class EnginePlayer(delegate: Player) : ForwardingPlayer(delegate) {
    override fun play() = PlayerEngine.playAction()
    override fun pause() = PlayerEngine.pauseAction()
    override fun seekTo(positionMs: Long) = PlayerEngine.seekTo(positionMs)
    override fun seekToNext() = PlayerEngine.next()
    override fun seekToPrevious() = PlayerEngine.prev()
    // ... seekToNextMediaItem / seekToPreviousMediaItem 同样映射
    override fun getAvailableCommands(): Player.Commands = ...
}
```

`getAvailableCommands()` 追加 `COMMAND_SEEK_TO_NEXT/PREVIOUS`，否则 PNR 不会画出切歌按钮。

### 3.4 封面：复用 Coil 缓存 + BitmapCallback

PNR 的 `MediaDescriptionAdapter.getCurrentLargeIcon()` 在通知构建时被调用。实现：

1. 先查 `artKey/artBitmap` 静态缓存，命中直接返回。
2. 未命中调用统一的 `requestArtwork(song, key) { bitmap -> ... }`；该函数会合并同一首歌的并发请求（标准通知 + PNR 可能同时要图），只发起一次 Coil 解码。
3. 图片到达后通过 `PlayerNotificationManager.BitmapCallback.onBitmap(bitmap)` 异步补到通知上。

`requestArtwork` 的细节：

- Coil `ImageLoader` 设置 `allowHardware(false)`（通知大图必须是软件 Bitmap）、`size(512)`。
- 结果回主线程 `finishArt()`，写入静态缓存，并派发所有等待中的回调。
- 失败记录 `artFailedKey`，避免重复请求坏链接。
- 非 Wear 的标准通知在 `finishArt()` 里 `startForeground` 原地刷新；Wear 由 PNR 的 callback 自己更新。

### 3.5 通知取消

PNR 的 `onNotificationCancelled(notificationId, dismissedByUser)`：

- 用户主动划掉（`dismissedByUser=true`）：`PlayerEngine.pauseAction()`，然后撤前台、`stopSelf()`。
- 服务销毁时 `setPlayer(null)` 导致的取消（`false`）：只撤前台/停服务，不重复暂停。

`onDestroy()` 里：

```kotlin
wearNotificationManager?.setPlayer(null)
wearNotificationManager = null
wearPlayer = null
NotificationManager.cancel(NOTIF_ID)
```

确保 PNR 不会在服务销毁后继续持有 Player 或残留通知。

### 3.6 刷新路径

- 服务已运行：`PlayerEngine.ensureStarted()` → `refreshNotification()`：
  - Wear：`wearNotificationManager.invalidate()`（没有则创建）；
  - 其他：`startForeground(NOTIF_ID, buildNotification())`。
- PNR 自身也监听 `Player`，切歌/播放状态变化会自动刷新，`invalidate()` 是兜底。

### 3.7 一个正式 APK 同时兼容 Wear OS 与普通安卓

- **不分 flavor、不拆 APK**：Wear / 非 Wear 是同一个 `applicationId`、同一个 APK，运行时按 `isWearOs` 选通知实现。
- **Manifest 声明 watch 特性为可选**：
  ```xml
  <uses-feature
      android:name="android.hardware.type.watch"
      android:required="false" />
  ```
  这样普通手机可以安装；Wear OS 也不会因为没有声明 watch 特性而拒绝。Google Play 分发时同样视为双形态可用。
- **通知实现三选一**：Wear → PNR；Android 9 非 Wear → RemoteViews；其余 → MediaStyle。三条路径共用同一个 `PlaybackService`、同一个 `PlayerEngine`、同一个 `MediaSession`。
- **minSdk 26**：对应 Wear OS 2.2+（Android 8.0+）/ Wear OS 3/4/5。Wear OS 2.0（Android 7.1，API 25）不在支持范围；如确实需要，必须单独做 API 25 的通知渠道/前台服务兼容，成本较高。
- **Release 验证**：`./gradlew assembleRelease` 已通过 R8 + lint；`media3-ui` 的 PNR 类保留在 release dex 中（见 R8 mapping），不会因为混淆被裁掉。

## 5. 完整代码

### 5.1 `PlaybackService.kt`（Wear 适配后的完整版本）

```kotlin
package com.netmusiclite.data

import android.app.Notification
import android.app.NotificationChannel
import android.app.NotificationManager
import android.app.PendingIntent
import android.app.Service
import android.content.Context
import android.content.Intent
import android.content.pm.PackageManager
import android.content.res.Configuration
import android.graphics.Bitmap
import android.graphics.drawable.BitmapDrawable
import android.graphics.drawable.Icon
import android.os.Build
import android.os.Handler
import android.os.IBinder
import android.os.Looper
import android.widget.RemoteViews
import androidx.media3.common.Player
import androidx.media3.ui.PlayerNotificationManager
import coil.ImageLoader
import coil.request.ImageRequest
import com.netmusiclite.MainActivity
import com.netmusiclite.R

/**
 * 播放保活前台服务（foregroundServiceType=mediaPlayback）。
 *
 * ★「播放中被杀后台」根因（2026-09-26）：全应用此前没有任何前台服务 —— ExoPlayer 跑在
 *   Activity 进程里，退到桌面/熄屏后进程被降为缓存进程，系统内存紧张时直接回收，播放中断。
 *   修法：PlayerEngine 在有播放意图（播放中/缓冲中）时经 [ensureStarted] 拉起本服务
 *   startForeground，把整个进程提升到前台服务优先级（ExoPlayer 与本服务同进程，一并受保护）；
 *   暂停/空闲即撤 —— 播放进度/队列随 player_state.json 持续落盘，进程被杀重进可续播。
 *   MediaSession 仍由 PlayerEngine 持有（手表表盘媒体控件/耳机线控不变），
 *   通知栏按键经 onStartCommand 直接驱动 PlayerEngine。通知按设备分三条路径：
 *   - Wear OS：PlayerNotificationManager（RemoteViews 在 Wear 上受限，不能自绘）；
 *   - Android 9 及以下非 Wear 手表：自定义 RemoteViews 紧凑控制条；
 *   - 其余：MediaStyle 关联同一会话。
 */
class PlaybackService : Service() {

    /** 通知封面专用解码器：关闭硬件位图（Notification 大图需软件 Bitmap） */
    private val artLoader by lazy {
        ImageLoader.Builder(applicationContext).allowHardware(false).build()
    }
    private val artHandler by lazy { Handler(Looper.getMainLooper()) }

    /** Wear OS 专用媒体通知管理器；非 Wear 设备为 null */
    private var wearNotificationManager: PlayerNotificationManager? = null
    private var wearPlayer: Player? = null
    private var wearManagerCreating = false

    /**
     * Wear OS 判定：只认 FEATURE_WATCH / uiMode。
     * 不能用屏幕宽度判断 —— 部分国产 Android 9 手表是小屏但不是 Wear OS，
     * 它们走 RemoteViews 兼容分支；真正的 Wear OS 走 PlayerNotificationManager。
     */
    private val isWearOs: Boolean
        get() = packageManager.hasSystemFeature(PackageManager.FEATURE_WATCH) ||
            (resources.configuration.uiMode and Configuration.UI_MODE_TYPE_MASK) ==
            Configuration.UI_MODE_TYPE_WATCH

    /** 手表判定：Wear OS 与部分国产手表不声明 FEATURE_WATCH，再看 uiMode 与小屏宽度 */
    private val isWatchDevice: Boolean
        get() = packageManager.hasSystemFeature(PackageManager.FEATURE_WATCH) ||
            (resources.configuration.uiMode and Configuration.UI_MODE_TYPE_MASK) ==
            Configuration.UI_MODE_TYPE_WATCH ||
            resources.configuration.smallestScreenWidthDp <= 240

    /**
     * Android 9 及以下的兼容通道：这类设备多为老手表/定制 ROM，
     * 通知中心会把 MediaStyle 渲染成「只有封面+歌名的媒体卡」，并丢弃 action 按钮。
     * 这类设备改用自定义 RemoteViews 紧凑控制条（封面 + 歌名 + 切歌/暂停/关闭）。
     */
    private val legacyCompact: Boolean
        get() = Build.VERSION.SDK_INT <= 28

    /**
     * 通知渠道：
     *  - Wear OS：playback_wear，由 PlayerNotificationManager 使用
     *  - Android 9 及以下/小屏手表：playback_watch，DEFAULT，避免被通知中心折叠
     *  - 其余设备：playback，LOW
     */
    private val channelId: String
        get() = when {
            isWearOs -> CHANNEL_ID_WEAR
            legacyCompact || isWatchDevice -> CHANNEL_ID_WATCH
            else -> CHANNEL_ID
        }

    override fun onBind(intent: Intent?): IBinder? = null

    override fun onCreate() {
        super.onCreate()
        instance = this
    }

    override fun onDestroy() {
        // Wear：先摘掉 Player，PlayerNotificationManager 会自行取消媒体通知
        wearNotificationManager?.setPlayer(null)
        wearNotificationManager = null
        wearPlayer = null
        if (isWearOs) {
            runCatching { getSystemService(NotificationManager::class.java).cancel(NOTIF_ID) }
        }
        instance = null
        super.onDestroy()
    }

    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        when (intent?.action) {
            ACTION_PLAY -> PlayerEngine.playAction()
            ACTION_PAUSE -> PlayerEngine.pauseAction()
            ACTION_NEXT -> PlayerEngine.next()
            ACTION_PREV -> PlayerEngine.prev()
            ACTION_STOP -> {
                // 通知右上角 X：暂停并撤掉通知（不销毁队列/当前歌，下次播放可续）
                PlayerEngine.pauseAction()
                stopForeground(STOP_FOREGROUND_REMOVE)
                stopSelf()
                return START_NOT_STICKY
            }
        }
        if (PlayerEngine.playbackActive) {
            startForeground(NOTIF_ID, foregroundNotification())
            if (isWearOs) ensureWearNotificationManager()
        } else {
            // ★ 2026-09-30 修「点播放后马上暂停 → 进程被杀」：
            //   ensureStarted() 判定播放意图成立时才调 startForegroundService()，但意图可能在
            //   本回调执行前就翻转（用户立刻暂停 / 起播失败撤销 fgWanted / 队列被替换）——
            //   旧版这时直接 stopForeground+stopSelf，从未调用 startForeground()，系统在 5s 后
            //   抛 RemoteServiceException: "Context.startForegroundService() did not then call
            //   Service.startForeground()" 杀掉整个进程（真机实测必崩，crash buffer 可查）。
            //   契约只对 startForegroundService 拉起的这次启动（本类走 ACTION_START）生效：
            //   先补一次 startForeground 满足契约，再立刻撤回（通知一闪即消，无残留）。
            if (intent?.action == ACTION_START) {
                startForeground(NOTIF_ID, foregroundNotification())
            }
            stopForeground(STOP_FOREGROUND_REMOVE)
            stopSelf()
        }
        return START_NOT_STICKY
    }

    private fun buildNotification(): Notification {
        if (isWearOs) return buildWearPlaceholder()
        val chId = channelId
        val importance = if (legacyCompact || isWatchDevice) {
            // 手表/老设备：DEFAULT 才不会被部分通知中心折叠；声音/震动仍关闭
            NotificationManager.IMPORTANCE_DEFAULT
        } else {
            NotificationManager.IMPORTANCE_LOW
        }
        ensureChannel(chId, importance)
        val song = PlayerEngine.current
        val playing = PlayerEngine.isPlaying
        val contentPi = contentPendingIntent()
        fun cmd(action: String): PendingIntent = PendingIntent.getService(
            this, action.hashCode(),
            Intent(this, PlaybackService::class.java).setAction(action),
            PendingIntent.FLAG_IMMUTABLE or PendingIntent.FLAG_UPDATE_CURRENT,
        )
        val builder = Notification.Builder(this, chId)
            .setSmallIcon(R.drawable.ic_notif_w)
            .setContentTitle(song?.title ?: "NetMusicLite")
            .setContentText(song?.artist ?: "")
            .setContentIntent(contentPi)
            .setCategory(Notification.CATEGORY_TRANSPORT)
            .setVisibility(Notification.VISIBILITY_PUBLIC)
            .setOnlyAlertOnce(true)
            // 老设备上不锁常驻：部分通知中心会把 ongoing 通知排除在「消息」列表之外；
            // 新设备仍保持常驻，避免被误滑掉。
            .setOngoing(!legacyCompact)
            // 媒体通知不显示「几点发的」；时间戳对正在播放的卡片没有意义
            .setShowWhen(false)
            .addAction(Notification.Action.Builder(
                Icon.createWithResource(this, R.drawable.ic_notif_prev), "上一首", cmd(ACTION_PREV)).build())
            .addAction(Notification.Action.Builder(
                Icon.createWithResource(
                    this, if (playing) R.drawable.ic_notif_pause else R.drawable.ic_notif_play),
                if (playing) "暂停" else "播放",
                cmd(if (playing) ACTION_PAUSE else ACTION_PLAY),
            ).build())
            .addAction(Notification.Action.Builder(
                Icon.createWithResource(this, R.drawable.ic_notif_next), "下一首", cmd(ACTION_NEXT)).build())
        val art = song?.let { notificationArt(it) }
        if (song != null) {
            // 专辑名放 subText（展开态显示），小屏上不挤占歌手行
            if (song.album.isNotBlank()) builder.setSubText(song.album)
            // 封面大图：首次构建时通常还没解码完，先出文字版，图到了再原地刷新
            art?.let { builder.setLargeIcon(it) }
        }
        if (legacyCompact) {
            // ★ 紧凑控制条（2026-10-18）：
            //   部分 Android 9 手表/定制 ROM 的通知中心会把普通通知画成大卡片、且不渲染 action；
            //   唯一能自定义的就是 RemoteViews —— 自己画一行「封面 + 歌名/歌手 + 上一首/
            //   播放暂停/下一首/关闭」，点按由 PendingIntent 直接驱动播放服务。
            val rv = RemoteViews(packageName, R.layout.notification_media_compact)
            rv.setTextViewText(R.id.notif_title, song?.title ?: "NetMusicLite")
            rv.setTextViewText(
                R.id.notif_artist,
                listOfNotNull(
                    song?.artist?.takeIf { it.isNotBlank() },
                    song?.album?.takeIf { it.isNotBlank() },
                ).joinToString(" · "),
            )
            if (art != null) {
                rv.setImageViewBitmap(R.id.notif_cover, art)
            } else {
                rv.setImageViewResource(R.id.notif_cover, R.mipmap.ic_launcher)
            }
            rv.setImageViewResource(
                R.id.notif_toggle,
                if (playing) R.drawable.ic_notif_pause else R.drawable.ic_notif_play,
            )
            rv.setOnClickPendingIntent(R.id.notif_root, contentPi)
            rv.setOnClickPendingIntent(R.id.notif_prev, cmd(ACTION_PREV))
            rv.setOnClickPendingIntent(R.id.notif_toggle, cmd(if (playing) ACTION_PAUSE else ACTION_PLAY))
            rv.setOnClickPendingIntent(R.id.notif_next, cmd(ACTION_NEXT))
            rv.setOnClickPendingIntent(R.id.notif_close, cmd(ACTION_STOP))
            builder.setCustomContentView(rv)
            builder.setCustomBigContentView(rv)
        } else {
            PlayerEngine.mediaSessionToken?.let { token ->
                builder.setStyle(
                    Notification.MediaStyle().setMediaSession(token).setShowActionsInCompactView(0, 1, 2),
                )
            }
        }
        if (Build.VERSION.SDK_INT >= 31) {
            builder.setForegroundServiceBehavior(Notification.FOREGROUND_SERVICE_IMMEDIATE)
        }
        return builder.build()
    }

    /** 前台通知内容：Wear 用占位通知（PNR 随后覆盖），其他设备直接构建完整通知 */
    private fun foregroundNotification(): Notification =
        if (isWearOs) buildWearPlaceholder() else buildNotification()

    /**
     * Wear OS 占位通知。
     *
     * PlayerNotificationManager 构建/更新通知是异步的，而 startForegroundService
     * 要求 5 秒内必须调用 startForeground。这里先用同一 ID / 渠道发一个最小通知满足契约，
     * PNR 随后会用同一 ID 把它覆盖成完整的媒体通知。
     */
    private fun buildWearPlaceholder(): Notification {
        ensureChannel(CHANNEL_ID_WEAR, NotificationManager.IMPORTANCE_DEFAULT)
        val song = PlayerEngine.current
        return Notification.Builder(this, CHANNEL_ID_WEAR)
            .setSmallIcon(R.drawable.ic_notif_w)
            .setContentTitle(song?.title ?: "NetMusicLite")
            .setContentText(song?.artist ?: "")
            .setContentIntent(contentPendingIntent())
            .setCategory(Notification.CATEGORY_TRANSPORT)
            .setVisibility(Notification.VISIBILITY_PUBLIC)
            .setOnlyAlertOnce(true)
            .setOngoing(true)
            .setShowWhen(false)
            .build()
    }

    /**
     * Wear OS 的媒体通知交给 PlayerNotificationManager：
     *  - 它内部走 NotificationCompat/MediaStyle，Wear OS 会按系统媒体模板渲染；
     *  - RemoteViews 在 Wear OS 上受限，不能沿用 Android 9 手表那套紧凑布局；
     *  - 它自己监听 Player，切歌/播放状态变化会自动刷新通知。
     *
     * 前台实体仍然是本服务：PNR 通过 NotificationListener.onNotificationPosted
     * 把通知交回来，我们再 startForeground 接管为前台通知。
     */
    private fun ensureWearNotificationManager(): PlayerNotificationManager? {
        if (!isWearOs) return null
        wearNotificationManager?.let { return it }
        if (wearManagerCreating) return null
        wearManagerCreating = true
        try {
            ensureChannel(CHANNEL_ID_WEAR, NotificationManager.IMPORTANCE_DEFAULT)
            val player = PlayerEngine.sessionPlayerOrNull(this) ?: return null
            val manager = PlayerNotificationManager.Builder(
                this,
                NOTIF_ID,
                CHANNEL_ID_WEAR,
            )
                .setMediaDescriptionAdapter(WearDescriptionAdapter())
                .setChannelNameResourceId(R.string.notif_channel_playing)
                .setChannelDescriptionResourceId(R.string.notif_channel_playing_desc)
                .setChannelImportance(NotificationManager.IMPORTANCE_DEFAULT)
                .setSmallIconResourceId(R.drawable.ic_notif_w)
                .setPlayActionIconResourceId(R.drawable.ic_notif_play)
                .setPauseActionIconResourceId(R.drawable.ic_notif_pause)
                .setPreviousActionIconResourceId(R.drawable.ic_notif_prev)
                .setNextActionIconResourceId(R.drawable.ic_notif_next)
                .setNotificationListener(object : PlayerNotificationManager.NotificationListener {
                    override fun onNotificationPosted(
                        notificationId: Int,
                        notification: Notification,
                        ongoing: Boolean,
                    ) {
                        // PNR 只负责内容；前台实体仍是本服务。同一 ID 接管，避免两条通知。
                        // 回调线程不保证是主线程，startForeground/业务暂停统一回主线程。
                        artHandler.post {
                            if (PlayerEngine.playbackActive) {
                                runCatching { startForeground(notificationId, notification) }
                            }
                        }
                    }

                    override fun onNotificationCancelled(notificationId: Int, dismissedByUser: Boolean) {
                        artHandler.post {
                            if (dismissedByUser) PlayerEngine.pauseAction()
                            stopForeground(STOP_FOREGROUND_REMOVE)
                            stopSelf()
                        }
                    }
                })
                .build()
            manager.setUsePreviousAction(true)
            manager.setUseNextAction(true)
            manager.setUsePlayPauseActions(true)
            manager.setUseStopAction(false)
            manager.setUseRewindAction(false)
            manager.setUseFastForwardAction(false)
            manager.setUsePreviousActionInCompactView(true)
            manager.setUseNextActionInCompactView(true)
            // 平台 MediaSession token：让 PNR 生成的 MediaStyle 与系统媒体面板/蓝牙共用同一会话
            PlayerEngine.mediaSessionToken?.let { manager.setMediaSessionToken(it) }
            val wrapped = EnginePlayer(player)
            wearPlayer = wrapped
            manager.setPlayer(wrapped)
            wearNotificationManager = manager
            return manager
        } finally {
            wearManagerCreating = false
        }
    }

    /** 播放状态/歌曲变化时刷新：Wear 交给 PNR，其他设备重建前台通知 */
    private fun refreshNotification() {
        if (isWearOs) {
            wearNotificationManager?.invalidate() ?: ensureWearNotificationManager()
        } else {
            startForeground(NOTIF_ID, buildNotification())
        }
    }

    private fun contentPendingIntent(): PendingIntent = PendingIntent.getActivity(
        this, 0,
        Intent(this, MainActivity::class.java)
            .addFlags(Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_SINGLE_TOP),
        PendingIntent.FLAG_IMMUTABLE or PendingIntent.FLAG_UPDATE_CURRENT,
    )

    private fun ensureChannel(id: String, importance: Int) {
        val nm = getSystemService(NotificationManager::class.java)
        if (nm.getNotificationChannel(id) == null) {
            nm.createNotificationChannel(
                NotificationChannel(id, getString(R.string.notif_channel_playing), importance).apply {
                    description = getString(R.string.notif_channel_playing_desc)
                    setShowBadge(false)
                    // 媒体通知不该发声/震动：控制按键的反馈由播放器自己负责。
                    // 注意通道属性只在首次创建时生效，老安装升级后仍沿用原来的配置。
                    setSound(null, null)
                    enableVibration(false)
                    lockscreenVisibility = Notification.VISIBILITY_PUBLIC
                },
            )
        }
    }

    /**
     * PNR 的文案/封面来源。
     * 封面复用 [requestArtwork] 的 Coil 缓存；未命中时先返回 null，图到了用
     * [PlayerNotificationManager.BitmapCallback.onBitmap] 异步补上。
     */
    private inner class WearDescriptionAdapter : PlayerNotificationManager.MediaDescriptionAdapter {
        override fun getCurrentContentTitle(player: Player): CharSequence =
            PlayerEngine.current?.title ?: "NetMusicLite"

        override fun createCurrentContentIntent(player: Player): PendingIntent =
            contentPendingIntent()

        override fun getCurrentContentText(player: Player): CharSequence? =
            PlayerEngine.current?.artist

        override fun getCurrentSubText(player: Player): CharSequence? =
            PlayerEngine.current?.album

        override fun getCurrentLargeIcon(
            player: Player,
            callback: PlayerNotificationManager.BitmapCallback,
        ): Bitmap? {
            val song = PlayerEngine.current ?: return null
            val key = artworkKey(song)
            if (key == artKey) return artBitmap
            requestArtwork(song, key) { bitmap -> if (bitmap != null) callback.onBitmap(bitmap) }
            return null
        }
    }

    /**
     * 通知封面：同步取缓存，未命中就交给 Coil 异步解码，完成后原地刷新通知。
     *
     * 为什么不在主线程同步解码：封面可达数百 KB，网络图还要等下载/解码，通知构建是主线程路径
     * （onStartCommand / startForeground），在这里做 I/O 会直接卡住表盘滑动。
     * 为什么用静态缓存：暂停会销毁服务，恢复时新实例重新建通知 —— 缓存留在 companion
     * 里可避免每次续播都闪一下无封面。
     */
    private fun notificationArt(song: Song): Bitmap? {
        val key = artworkKey(song)
        if (key == artKey) return artBitmap
        if (key == artLoadingKey || key == artFailedKey) return null
        requestArtwork(song, key) { /* 标准通知由 finishArt 统一刷新 */ }
        return null
    }

    private fun artworkKey(song: Song) = "${song.id}:${song.coverUrl.orEmpty()}"

    /**
     * 统一的封面加载入口：标准通知、Wear 的 PNR 适配器都走这里。
     * 同一首歌并发请求会合并成一次网络/解码，回调按顺序在主线程派发。
     */
    private fun requestArtwork(song: Song, key: String, onResult: (Bitmap?) -> Unit) {
        if (key == artKey && artBitmap != null) {
            onResult(artBitmap)
            return
        }
        if (key == artFailedKey) {
            onResult(null)
            return
        }
        synchronized(artCallbacks) {
            if (key == artLoadingKey) {
                artCallbacks.getOrPut(key) { mutableListOf() }.add(onResult)
                return
            }
            artLoadingKey = key
            artCallbacks[key] = mutableListOf(onResult)
        }
        val model = PlayerEngine.artworkModelFor(song)
        if (model == null) {
            artHandler.post { finishArt(key, null) }
            return
        }
        val request = ImageRequest.Builder(applicationContext)
            .data(model)
            .size(512)            // 通知大图上限约 64dp@xxxhdpi，512 足够且省内存
            .allowHardware(false) // Notification 大图必须是软件位图
            .listener(
                onSuccess = { _, result ->
                    val bitmap = (result.drawable as? BitmapDrawable)?.bitmap
                    artHandler.post { finishArt(key, bitmap) }
                },
                onError = { _, _ ->
                    artHandler.post { finishArt(key, null) }
                },
            )
            .build()
        artLoader.enqueue(request)
    }

    private fun finishArt(key: String, bitmap: Bitmap?) {
        val callbacks: List<(Bitmap?) -> Unit>
        synchronized(artCallbacks) {
            artLoadingKey = null
            if (bitmap != null) {
                artKey = key
                artBitmap = bitmap
                artFailedKey = null
            } else {
                // 失败也记下来，避免每次播放/暂停都重新发起同一个坏链接
                artFailedKey = key
            }
            callbacks = artCallbacks.remove(key) ?: emptyList()
        }
        callbacks.forEach { it(bitmap) }
        // 非 Wear 的标准通知：图到了原地刷新（Wear 由 PNR 的 BitmapCallback 自己更新）
        if (bitmap != null && !isWearOs && PlayerEngine.playbackActive) {
            instance?.let { runCatching { it.startForeground(NOTIF_ID, it.buildNotification()) } }
        }
    }

    companion object {
        private const val CHANNEL_ID = "playback"
        private const val CHANNEL_ID_WATCH = "playback_watch"
        private const val CHANNEL_ID_WEAR = "playback_wear"
        private const val NOTIF_ID = 42
        const val ACTION_START = "com.netmusiclite.playback.START"
        const val ACTION_PLAY = "com.netmusiclite.playback.PLAY"
        const val ACTION_PAUSE = "com.netmusiclite.playback.PAUSE"
        const val ACTION_NEXT = "com.netmusiclite.playback.NEXT"
        const val ACTION_PREV = "com.netmusiclite.playback.PREV"
        const val ACTION_STOP = "com.netmusiclite.playback.STOP"

        /** 运行中服务实例（同进程直引用：通知原地刷新用） */
        @Volatile
        private var instance: PlaybackService? = null

        // 封面缓存：键 = 歌曲 id + 封面地址。服务暂停会被销毁，恢复时新实例靠这里避免闪白。
        @Volatile private var artKey: String? = null
        @Volatile private var artBitmap: Bitmap? = null
        @Volatile private var artLoadingKey: String? = null
        @Volatile private var artFailedKey: String? = null

        // 同一首歌的并发封面请求回调（标准通知 + Wear PNR 适配器），只发一次网络/解码
        private val artCallbacks = mutableMapOf<String, MutableList<(Bitmap?) -> Unit>>()

        /**
         * PlayerEngine 在播放意图出现/歌曲切换时调用（主线程）。
         * 服务已运行：同进程直调 startForeground 原地刷新通知 —— 不经 start 系调用，
         * 后台自动切歌的路径也放行（31+ 的后台 FGS 启动限制只拦「启动」，不拦「已运行」）。
         * 未运行：startForegroundService 拉起（正常都在用户前台操作时发生）；极端时序
         * （蓝牙耳机从后台唤起播放）可能被系统拒绝，捕获后仅本次失去保护，不影响出声。
         */
        fun ensureStarted(ctx: Context) {
            instance?.let { s ->
                if (PlayerEngine.playbackActive) s.refreshNotification()
                return
            }
            runCatching {
                ctx.startForegroundService(Intent(ctx, PlaybackService::class.java).setAction(ACTION_START))
            }
        }

        /** 暂停/空闲即撤：stopService 对运行中前台服务无后台限制；未运行时为无害 no-op */
        fun stop(ctx: Context) {
            runCatching { ctx.stopService(Intent(ctx, PlaybackService::class.java)) }
        }
    }
}
```

```kotlin
package com.netmusiclite.data

import androidx.media3.common.ForwardingPlayer
import androidx.media3.common.Player

/**
 * 把系统/通知下发的 Player 命令翻译回 [PlayerEngine] 的业务动作。
 *
 * 为什么不能直接让 Media3 / PlayerNotificationManager 操作 ExoPlayer：
 * NetMusicLite 的队列、播放模式、一起听协调全在 PlayerEngine 里，而 ExoPlayer
 * 每次只 `setMediaItem` 载入**一首**（见 `PlayerEngine.load`），直接
 * `seekToNextMediaItem()` 只会原地不动。
 *
 * 使用方：
 *  - [MusicSessionService]：系统媒体界面的 Media3 会话
 *  - [PlaybackService]：Wear OS 的 PlayerNotificationManager
 */
internal class EnginePlayer(delegate: Player) : ForwardingPlayer(delegate) {

    override fun play() = PlayerEngine.playAction()

    override fun pause() = PlayerEngine.pauseAction()

    /** 系统可能直接写 playWhenReady（媒体键/局域网控制器），同样走业务路径 */
    override fun setPlayWhenReady(playWhenReady: Boolean) {
        if (playWhenReady) play() else pause()
    }

    override fun seekTo(positionMs: Long) = PlayerEngine.seekTo(positionMs)

    // 上/下一首：新老控制器的命令 ID 不同，四个入口都要接
    override fun seekToNext() = PlayerEngine.next()
    override fun seekToPrevious() = PlayerEngine.prev()
    override fun seekToNextMediaItem() = PlayerEngine.next()
    override fun seekToPreviousMediaItem() = PlayerEngine.prev()

    /** 系统媒体面板的关闭键：与平台会话的 onStop 保持一致，只暂停不销毁会话 */
    override fun stop() = PlayerEngine.pauseAction()

    /**
     * 追加「上/下一首」命令位：ExoPlayer 里始终只有一首歌（队列在 PlayerEngine），
     * 默认命令集不含这几个位，系统 UI / 通知就不会画出切歌按钮。
     */
    override fun getAvailableCommands(): Player.Commands =
        super.getAvailableCommands().buildUpon()
            .add(Player.COMMAND_SEEK_TO_NEXT_MEDIA_ITEM)
            .add(Player.COMMAND_SEEK_TO_PREVIOUS_MEDIA_ITEM)
            .add(Player.COMMAND_SEEK_TO_NEXT)
            .add(Player.COMMAND_SEEK_TO_PREVIOUS)
            .build()
}
```

## 6. 移植到上游新版：步骤清单

1. **加依赖**
   - `implementation("androidx.media3:media3-ui:1.5.1")`
   - 必须与 `media3-exoplayer` / `media3-session` **同版本**，否则 `media3-common` 会出现两份、运行时 cast 崩溃。

2. **抽取 `EnginePlayer`**
   - 新增 `EnginePlayer.kt`（见 5.2）。
   - 把 `MusicSessionService` 里原有的私有 `EnginePlayer` 删掉，直接用共享类。

3. **改 `PlaybackService`**
   - 新增 `isWearOs`、`wearNotificationManager`、`wearPlayer`、`wearManagerCreating`。
   - `channelId` 增加 `playback_wear` 分支。
   - `onStartCommand`：`startForeground` 用 `foregroundNotification()`；Wear 再 `ensureWearNotificationManager()`。
   - `onDestroy`：`setPlayer(null)` + 取消通知。
   - 新增 `buildWearPlaceholder()`、`ensureWearNotificationManager()`、`refreshNotification()`、`WearDescriptionAdapter`。
   - 封面逻辑从「单首请求」改成 `requestArtwork` + 回调队列，标准通知和 PNR 共用。
   - `ensureStarted()` 里服务已运行的分支改为 `refreshNotification()`，不再直接 `startForeground(buildNotification())`。

4. **加字符串**
   - `notif_channel_playing`、`notif_channel_playing_desc`。

5. **Manifest 声明双形态**
   - 增加 `<uses-feature android:name="android.hardware.type.watch" android:required="false" />`。
   - 不要加 `required="true"`，否则普通手机会被应用商店过滤；也不要把 Wear 做成独立 flavor，除非确实需要两套资源。

6. **构建测试**
   - 按第 7 节清单；至少分别用 `assembleDebug` 和 `assembleRelease` 各跑一次。

### 合并时容易踩的坑

- **Wear OS 不要用 RemoteViews**：即使布局在手机上正常，Wear 也会折叠/降级；Wear 必须走 PNR。
- **不要用屏幕宽度判断 Wear**：国产 Android 9 手表会误判。只认 `FEATURE_WATCH` / `uiMode=WATCH`。
- **PNR 必须拿到 `EnginePlayer` 包装**：直接传 ExoPlayer，切歌按钮会原地不动，暂停也不会同步业务状态。
- **PNR 与前台服务必须同 ID**：`NOTIF_ID` 同时给 PNR 和 `startForeground`，否则会出现两条通知。
- **5 秒契约**：PNR 异步发通知，必须先发占位通知再 `setPlayer`。
- **销毁顺序**：先 `setPlayer(null)`，再置空引用/取消通知；不要直接 `release()` ExoPlayer（它归 PlayerEngine）。
- **media3 版本对齐**：`media3-ui` 必须与 `media3-exoplayer` / `media3-session` 完全一致。

- [ ] 冷启动后立刻点歌（`ensurePlayer` 抢跑）通知仍正常。

回归（非 Wear）：

- [ ] Android 9 非 Wear 手表：仍是 RemoteViews 紧凑条，四个按钮可用。
- [ ] Android 10+ 手机/手表：仍是 MediaStyle 通知。
- [ ] Android 13+ 通知权限拒绝时：播放正常，仅无通知。
- [ ] 蓝牙媒体键、锁屏/系统媒体面板仍能控制。

同一个正式 APK：

- [ ] 同一个 `app-release.apk` 能安装到普通安卓手机和 Wear OS 手表，无需拆包。
- [ ] `aapt2 dump badging` 显示 `uses-feature-not-required: android.hardware.type.watch`。
- [ ] 手机上走 MediaStyle / 通知栏；手表上走 PNR / 系统媒体模板。

## 8. 已知限制

1. **PNR 使用系统媒体模板**，外观由 Wear OS 决定，不能像前置的 RemoteViews 那样完全自绘；OEM 顶部那条带「词/X」的私有媒体条仍无法直接插入。
2. **暂停即撤通知**：沿用原工程策略，暂停后服务停止、PNR 取消通知，不能从通知栏直接续播。
3. **`media3-ui` 会增加 APK 体积**（PNR 及其依赖），但这是 Wear 兼容的必要成本。
4. **PNR 的通知 ID 与前台服务 ID 必须一致**；如果上游改了 `NOTIF_ID`，两处要同步。
5. **Wear OS 2/3/4 的通知模板存在差异**，PNR 会按系统版本适配；自定义文案长度建议控制在两行内。
6. **minSdk 26**：支持 Wear OS 2.2+ / 3 / 4 / 5；Wear OS 2.0（Android 7.1，API 25）无法安装。若必须支持 API 25，需要单独补 `NotificationChannel` / `startForegroundService` 的旧版本分支。
