# 移植到上游 1.32 的对接指南

> 适用对象：作者 1.32（`com.ncm.watch`，versionCode 56）。
> 本文只讲「把 1.0.3 分支上新增的功能搬到 1.32」——**不是合并反编译产物**，原因见第 1 节。
> 配套代码在 [`port-1.32/`](port-1.32/)，可直接拷进工程。

---

## 1. 为什么不是「反编译出源码再改」

1.32 是 Release 包，R8 混淆过，能反编译出 6022 个类（jadx 1.5.1）、能完整还原 smali 与资源（apktool 2.11.1），但**得不到可编译的工程**：

- 界面全部是 Jetpack Compose。每个 `@Composable` 编译后裂成几十个 lambda 合成类，例如 `HomeScreenKt$HomeScreen$4$invoke$lambda$6$lambda$5$$inlined$items$1`。jadx 只能还原出带 `Composer` 参数、`$default` 位掩码的伪 Java，既不能编译，也无法逆向成 Kotlin。
- 包名、类名、框架类都被改写（`z1.X` = media3 `Player`、`p4.AbstractC1536l` = `Intrinsics`），即便逐类重写也无法保证行为一致。
- 反过来，在 smali 层直接改 APK 只能做「替换某个非 UI 类」这种手术，做不了新增 Compose 页面。

**结论**：功能要进 1.32，必须在 1.32 的 Kotlin 源码上改。本文给出逐文件、逐位置的改法。

## 5. 通知与媒体控制（第 1、2 项功能）

### 5.1 加依赖

```kotlin
implementation("androidx.media3:media3-ui:1.5.1")   // 与现有 media3 版本保持一致
```

`PlayerNotificationManager` 在 1.32 里会被 R8 裁掉（没人引用），加了依赖并真正调用后才会保留。

### 5.2 PlayerEngine 的四处改动

**① 竞态修复（必须做，否则 1.32 的通知会随机退化成普通通知）**

1.32 现状：

```kotlin
private fun ensurePlayer(): ExoPlayer {
    warmUp()
    player?.let { return it }
    return buildExoPlayer().also { configPlayer(it); player = it }   // ← 没建会话
}
```

`PlayerEngine$warmUp$1` 里：`if (player == null) { … initMediaSession() } else { p.release() }`。
预热协程发现 `player` 已被 `ensurePlayer()` 抢先建好 → 走 `release()` 分支 → **`initMediaSession()` 永不执行**。
触发条件：系统媒体服务提前 bind、冷启动 300ms 内点歌。表现为通知没有 MediaStyle、蓝牙线控与手表「正在播放」卡片失效。

改法：`ensurePlayer()` 的 `also` 块里补 `ensureMediaSession()`，预热协程的 `else` 分支也补一次。

**② `initMediaSession()` 补 flags**

```kotlin
private fun initMediaSession() {
    if (mediaSession != null) return
    val ms = MediaSession(appCtx, "NetMusicLite")
    ms.setFlags(
        MediaSession.FLAG_HANDLES_MEDIA_BUTTONS or
            MediaSession.FLAG_HANDLES_TRANSPORT_CONTROLS
    )
    // …原有 setCallback / setSessionActivity / setActive 不动
}
```

**③ `updateMediaSession()` 补 `ART_URI`**

1.32 只写了 `ALBUM_ART_URI`。部分手表「正在播放」卡片只读 `ART_URI`，两个都写才不会出现「锁屏有图、手表没图」。

**④ 新增 `sessionPlayerOrNull()`**

PNR 需要拿到 ExoPlayer 引用，但 1.32 的 `player` 是 private：

```kotlin
fun sessionPlayerOrNull(ctx: Context): Player? {
    if (!::appCtx.isInitialized) init(ctx)
    return runCatching { ensurePlayer() }.getOrNull()
}
```

只借引用，不交所有权 —— 服务侧绝不可 `release()`。

### 5.3 替换 PlaybackService

直接用 [`port-1.32/PlaybackService.kt`](port-1.32/PlaybackService.kt) 覆盖。相对 1.32 现有实现的变化：

- 三条设备路径：Wear → PNR；Android ≤9 非 Wear → RemoteViews 紧凑条；其余 → MediaStyle。
- 通知加封面大图（Coil 后台解码 + 静态缓存，解码完原地刷新，不阻塞主线程）。
- 加关闭 X（`ACTION_STOP`：暂停 + 撤通知，保留队列与当前歌）。
- 渠道按设备分三条，全部 `setSound(null)` + `enableVibration(false)`。
- 五个 action 常量沿用 1.32 的 `com.ncm.watch.playback.*`，只新增 `STOP`。
- 图标按 `AppearancePrefs.isM3e()` 在 `ic_notif_*` / `ic_m3e_notif_*` 之间切换。

⚠️ `AppearancePrefs.isM3e()` 在 1.32 里若是属性而非函数，写成 `AppearancePrefs.isM3e`，按 IDE 提示改。

⚠️ EnginePlayer：优先用 `MusicSessionService.EnginePlayer(player)`；若该嵌套类不可访问，再把 [`port-1.32/EnginePlayer.kt`](port-1.32/EnginePlayer.kt) 加进 `data/`。

### 5.4 资源

`notification_media_compact.xml` 用的 id 全是新 id（`notif_root/notif_cover/notif_title/notif_artist/notif_prev/notif_toggle/notif_next/notif_close`），不会和 1.32 现有资源冲突。

## 6. 歌单收藏与推荐（第 3、4 项功能）

### 6.1 数据层

1.32 的 `PlaylistItem` 已有 `subscribed` / `specialType`，缺 `creatorName`（收藏的官方动态歌单要显示创建者）：

```kotlin
data class PlaylistItem(
    val id: Long,
    val name: String,
    val coverUrl: String?,
    val trackCount: Int,
    val playCount: Long,
    val isMine: Boolean,
    val subscribed: Boolean = false,        // 已有
    val specialType: Int = 0,               // 已有
    val creatorName: String? = null,        // 新增
)
```

`userPlaylists` 现在是单页 40 条、`subscribed` 写死 `false`。改成：

- `subscribed = o.optBoolean("subscribed", false) || o.optInt("subscribed", 0) == 1`（接口两种返回都出现过）；
- `creatorName = o.optJSONObject("creator")?.optString("nickname")`；
- 按 `limit=100` 翻页，直到 `more == false` 或本页无新增；短页按实际条数推进，避免漏歌单。

### 6.2 接口

1.32 没有这三个接口，需要新增（实测口径见 [`2026-10-18-歌单收藏与推荐.md`](2026-10-18-歌单收藏与推荐.md)）：

| 用途 | 接口 | 方式 |
|---|---|---|
| 推荐歌单 | `/personalized/playlist?limit=12` | 明文 GET |
| 推荐新歌 | `/personalized/newsong?type=recommend&limit=12` | 明文 GET |
| 收藏/取消歌单 | `/playlist/subscribe`，`t=1/0` | `weWrite` + `__csrf` |

推荐接口用明文 GET 是有原因的：`weapi` 版本在本项目当前的请求头组合下返回 `-460`（风控），明文 GET 稳定。

### 6.3 界面

- `LibraryScreens`：两个 tab 改为 `创建` / `收藏的专辑和歌单`；收藏栏 = 「我收藏的专辑」+「我收藏的歌单」两段。
- 新增 `RecommendScreen`：推荐歌单（可一键收藏、可换一批）+ 推荐新歌（点击起播、可换一批）。
- `HomeScreen.kt` 的 `homeItems` 在 `"daily_recommend"` 后插一项：

```kotlin
HomeItem("推荐", ncmIcons.recognize, "recommend")
```

- `AppNav.kt` 照 `"daily_recommend"` 那行复制一份，路由改 `"recommend"`，内容为 `RecommendScreen(nav)`。

完整代码见 [`2026-10-18-推荐页与收藏整合.md`](2026-10-18-推荐页与收藏整合.md)。

## 8. 已知限制

1. **暂停即撤通知**（沿用 1.32 现有策略）：暂停后通知消失，无法从通知栏续播。要改需要把 `syncForeground` 的判定从「有播放意图」放宽到「有当前歌」。
2. **OEM 顶部媒体条**（如 ColorOS 在「消息」列表上方那条带「词」和「X」的控件）是系统级私有能力，只对系统内置/合作音乐 App 开放，第三方无法插入。
3. **Wear OS 的 PNR 表现依赖系统模板**，不同 Wear 版本间距/按钮数量略有差异，属正常。
4. **收藏是写接口**，需要登录态。匿名状态下服务端会拒绝，界面只提示失败。
5. `minSdk 26` 对应 Wear OS 2.2+；Wear OS 2.0（API 25）装不上。
