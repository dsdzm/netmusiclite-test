## 编写约定

以后每个功能改动都新增一份：

```
docs/updates/YYYY-MM-DD-简短主题.md
```

文档至少包含以下 7 节：

1. **背景/问题**：现象、复现条件、为什么要做。
2. **实现原理**：调用链、关键设计、为什么不用另一种方案。
3. **改动文件清单**：文件 + 修改/新增 + 作用。
4. **完整代码或 diff**：让上游可以直接复制或对照合并。
5. **移植步骤**：按文件、按插入点列出，包含容易踩的坑。
6. **测试清单**：真机/模拟器逐项验证。
7. **已知限制与兼容性**：ROM 差异、API 限制、本次没做的部分。

并在根 `README.md` 的「更新文档」一节添加入口链接。
